❓ COMMON QUESTIONS

Q: How does sensor.js work?
A: Captures clicks in mousedown event, buffers locally, sends batch
   every 5 seconds to /api/ingest endpoint.

Q: Why 5 seconds?
A: Balances latency (real-time enough) with efficiency (reduces
   network requests from 1000s to 200 batches).

Q: What if user closes tab before 5-second flush?
A: Beacon API ensures final data sent (fire-and-forget at OS level).

Q: Where is click position stored?
A: Currently just buffered and sent. Phase 2 maps it to section.
   Full x,y coordinates not stored (privacy + storage efficiency).

Q: How many clicks can it handle?
A: 1000s per session, unlimited sessions. Indexes handle scale.

Q: Is data secure?
A: No encryption yet (will add HTTPS in production). API keys in
   .env file are git-ignored. Never commit .env!
